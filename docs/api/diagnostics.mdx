---
title: Diagnostics
description: Diagnostics words — PrintStack and DumpTree for debugging
---

Diagnostics words inspect the widget stack and tree at runtime, available in any
`Build()` method. They are the Factor `.s` equivalent brought into Beef — every error
already includes a stack dump via `Fail()`, and these words give you the same visibility
on demand.

## PrintStack

```beef
// In any Build() or word body:
PrintStack();
```

Outputs the current widget stack contents to the console:

```
--- stack (3 items, top last) ---
  Mark: "VStack"
  [str "Count: 5"]
  [Elem Label]
```

The stack prints top-last (stack bottom first, stack top last). Each item shows its
type tag and value. Used automatically by `Fail()` on every error.

## DumpTree

```beef
// On your App instance, after RebuildIfNeeded():
app.RebuildIfNeeded();
app.DumpTree();
```

Outputs an indented XML-like dump of the entire widget tree. The dump iterates all three
bags — Component, Property, and Behavior — so every attached type appears through its
`Describe` override without the framework knowing it exists:

```
# ---- [UI Tree Dump] ---- #
<VStack Padding=16 Key=-1 Rect=(0,0, 800x600)>
  <Label Text="Counter" FontSize=24 Color=RGBA(255,255,255,255) Padding=0 Key=-1 Rect=(...)/>
  <Label Text="Count: 5" Color=RGBA(255,0,0,255) FontSize=14 Padding=0 Key=-1 Rect=(...)/>
  <HStack Spacing=2 Padding=0 Key=-1 Rect=(...)>
    <Button Text="+" Fill=RGBA(80,80,80,255) Radius=4 Stroke=RGBA(120,120,120,255)
            StrokeWidth=1 Radius=4 OnClick Padding=8 Key=-1 Rect=(...) FixedSize(120,20)/>
    <Spacer Padding=0 Key=-1 Rect=(...)/>
    <Button Text="-" Fill=RGBA(80,80,80,255) Radius=4 Stroke=RGBA(120,120,120,255)
            StrokeWidth=1 Radius=4 OnClick Padding=8 Key=-1 Rect=(...) FixedSize(120,40)/>
  </HStack>
</VStack>
# ---- [/UI Tree Dump] ---- #
```

Each widget shows its name, then all non-empty `Describe` output from each bag, followed by
the universal `Padding`, `Key`, and `Rect` fields. A user's custom `Component`, `Property`,
or `Behavior` appears here through its `Describe` override — zero registration.

In the current SDL3 prototype, `DumpTree()` is mainly useful for debugging layout issues
(post-rebuild rects are printed).
