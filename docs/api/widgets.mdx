---
title: Widgets
description: Widget words — Label, Button, Stack, Spacer — with stack effects
---

Widget words push a `Widget` onto the stack. They consume their inputs from the stack first,
then push the new widget (the pop-inputs-first rule). This is Factor's own discipline
surfacing in Beef — consume inputs before pushing outputs, so the stack is always in a
predictable state.

## Label

```
( string -- widget )
```

```beef
// Primitive form
Str("Hello"); Label();

// Sugar
Label("Hello");
```

Creates a widget named `"Label"` with a `TextComponent` (Component bag) holding the string
and a `TextStyleProperty` (Property bag) with default font size and color.
To style the label, apply modifier words after it:

```beef
Label("Title"); FontSize(24); TextColor(.White);
```

## Button

```
( string -- widget )
```

```beef
// Primitive form
Str("+"); Button(); OnClick(handler);

// Sugar
Button("+"); OnClick(handler);
```

Creates a widget named `"Button"` with:

| Bag | Type | What |
|---|---|---|
| Component | `TextComponent` | The label text |
| Component | `Interior` | Default gray fill, radius 4 |
| Component | `Boundary` | Border stroke, width 1, radius 4 |
| Property | `TextStyleProperty` | `FontSize = 12`, `TextColor = Black` |
| Widget field | `Padding` | 8 on all sides |

A `Button` is just a styled label; clickability arrives when `OnClick` attaches an
`OnClickBehavior` to the Behavior bag.

**Overriding defaults:** any property can be changed by re-focusing after the word:

```beef
Button("Delete");
Background(scope () => { Fill(.Red); Radius(6); });
```

## Spacer

```
( -- widget )
```

```beef
Spacer();
```

Pushes a widget named `"Spacer"` with no components, properties, or behaviors. The layout
pass treats it as a flex-grow gap; it absorbs all leftover space in the main axis of its
parent stack.

```beef
HStack(scope () => {
    Button("Left");
    Spacer();          // pushes buttons apart
    Button("Right");
});
```

## Container stacks

Containers use a **triplet pattern**: `_Prefix()` opens, body words run, `Prefix_()` closes.
The delegate-block form is sugar:

### HStack

```
( mark child* widget -- widget )
```

| Word | Description |
|---|---|
| `_HStack()` | Push a named marker |
| `HStack_()` | Create `"HStack"` widget with `StackLayout(Axis.Horizontal)`, collect children back to marker |
| `HStack(delegate void())` | Sugar: `_HStack(); body(); HStack_()` |

```beef
HStack(scope () => {
    Button("+");
    Button("-");
}); Spacing(4);
```

### VStack

Same pattern as HStack but with `StackLayout(Axis.Vertical)`.

```beef
VStack(scope () => {
    Label("Title");
    Label("Subtitle");
}); Padding(8);
```

### Scrollable

```
( mark child* widget -- widget )
```

| Word | Description |
|---|---|
| `_Scrollable()` | Push a named marker |
| `Scrollable_()` | Create `"Scrollable"` widget with `StackLayout(Axis.Vertical)` **and** a `ScrollView` marker, collect children back to marker |
| `Scrollable(delegate void())` | Sugar: `_Scrollable(); body(); Scrollable_()` |

A `Scrollable` is a stack that carries a `ScrollView` component, so the mouse wheel scrolls
its children and the scroll offset survives rebuilds (it lives in the persistent
[retained `Node` tree](/concepts/interaction-pipeline) keyed by `StableKey`). It is vertical by
default; set the axis with `Horizontal()`/`Vertical()`.

It does **not** clip on its own — clipping is a separate composable capability. Give it a
bounded main-axis size and add `Clip()` so its content overflows into a scroll viewport
instead of the container growing to fit:

```beef
Scrollable(scope () => {
    for (let t in mTodos)
        TodoRow(t.id, t.text, new () => { Remove(t.id); });
}); Height(.Fixed(240)); Spacing(6); Clip();
```

See [`Clip`, `Vertical`, `Horizontal`](/api/modifiers#clipping-and-scroll-direction) and the
[Scroll & clipping](/concepts/interaction-pipeline) note.

### Paired primitives for cross-function factoring

When a single delegate block isn't enough (e.g. children generated across multiple functions),
use the paired primitives directly:

```beef
void HeaderSection()
{
    _VStack();
    Label("Header");
}

void FooterSection()
{
    Label("Footer");
    VStack_();  // closes the VStack opened by HeaderSection
}
```

The paired primitives are public and safe; the named-marker mechanism catches mismatches.
