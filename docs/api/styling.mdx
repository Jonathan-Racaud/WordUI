title: Styling
description: Pen blocks for styling — Background, Border, Fill, Stroke, Radius, StrokeWidth
---

Pen blocks are a modifier sub-vocabulary for styling — they open a "pen" on the stack that
collects property assignments, then attach them all at once using `ReplaceComponent`. This
means re-running a pen block on a widget that already has an `Interior` or `Boundary`
replaces the old one instead of triggering a duplicate error.

## Background (Interior pen)

```beef
Button("Submit");
Background(scope () => {
    Fill(.Blue);
    Radius(6);
});
```

Uses the paired-primitive pattern with `ReplaceComponent`:
- `_Interior()` — pushes a marker, then an `Interior` pen
- Pen property words modify the pen on top
- `Interior_()` — pops the pen, finds the marker, calls `ReplaceComponent` to attach the
  `Interior` to the widget below (replacing any existing `Interior`)

Stack effect:
```
_Interior   ( widget -- widget mark pen )
Fill        ( widget mark pen color -- widget mark pen )
Radius      ( widget mark pen float -- widget mark pen )
Interior_   ( widget mark pen -- widget )
```

## Border (Boundary pen)

```beef
Button("Outline");
Border(scope () => {
    Stroke(.White);
    StrokeWidth(2);
    Radius(6);
});
```

Same pattern as Background but with `Boundary`:
- `_Border()` / `Border_()` / `Border(delegate)`
- Closing calls `ReplaceComponent` to replace any existing `Boundary`

## Pen property words

### Fill

```
( pen color -- pen )
```

Sets the fill color on an active `Interior` pen. Must be inside a `Background { }` block;
calling it outside errors with: `"no active Interior — are you inside a Background block?"`

```beef
Background(scope () => { Fill(.(255, 0, 0, 255)); });
```

### Stroke

```
( pen color -- pen )
```

Sets the stroke color on an active `Boundary` pen. Must be inside a `Border { }` block.

```beef
Border(scope () => { Stroke(.White); });
```

### Radius

```
( pen float -- pen )
```

Sets the corner radius on either an `Interior` or `Boundary` pen. Works inside either
`Background { }` or `Border { }`. Errors if no pen is active.

```beef
Background(scope () => { Fill(.Red); Radius(8); });
Border(scope () => { Stroke(.White); Radius(8); });
```

### StrokeWidth

```
( pen float -- pen )
```

Sets the stroke width on an active `Boundary` pen. Must be inside a `Border { }` block.

```beef
Border(scope () => { Stroke(.Black); StrokeWidth(3); });
```

## Replacement semantics

Pen blocks use `ReplaceComponent`, not `AttachComponent`. This is the key difference from
ordinary modifier words: a second pen block of the same kind replaces the first.

```beef
// This works: the second Background replaces the first Interior
Button("Toggle");
Background(scope () => { Fill(.Blue); Radius(6); });
Background(scope () => { Fill(.Green); Radius(10); }); // replaces, no error

// This would fail: two TextColor calls mutate the same TextStyleProperty in place
Label("X"); TextColor(.Red); TextColor(.Blue); // fine — mutates in place
```

The general rule: pen blocks use replacement semantics (they own their Component slot);
ordinary modifier words use mutation semantics (they mutate an existing instance in place,
creating one via get-or-create if absent).

## Combining pens

Pens compose freely; you can have both a Background and a Border on the same widget:

```beef
Button("Styled");
Background(scope () => { Fill(.Blue); Radius(8); });
Border(scope () => { Stroke(.White); StrokeWidth(2); Radius(8); });
```

## Inside a state body (patch mode)

These same words behave differently when they run inside an interaction state body
(`IfHover`, `IfPressed`, or any `IfActive<T>` — see the
[Interaction Pipeline](/concepts/interaction-pipeline)). Instead of mutating the widget's
base components, each **records the individual field it touched** onto a `StatePatch`, which
the draw pass blends over the base only while the state is active:

```beef
Button("+");
IfHover(scope () => {
    Fill(.(90, 90, 90, 255));   // records a Fill patch; no Background block needed
});
```

- `Fill`, `Stroke`, `StrokeWidth` (and the text words `TextColor`, `FontSize`) record their
  field onto the patch and early-return.
- `Background { … }` and `Border { … }` become transparent pass-throughs — there is no pen to
  open in patch mode; the enclosed field words do the recording.
- `Radius` is **not an animatable patch field yet**, so it is ignored inside a state body.

Wrap a recording word in [`Transition`](/api/modifiers#transition) to animate that field.
