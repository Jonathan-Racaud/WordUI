WordUI is built in milestones, each ending in a runnable demo that validates one layer of the
stack. The goal is to de-risk every layer before the next one depends on it, so that we never
build on an unproven foundation.

## Milestones

| Milestone | Status | What |
|---|---|---|
| **M0** — SDL window | ✅ Complete | SDL3 window opens, event loop, close on ✕. De-risked Beef+SDL3 linkage before any framework code depended on it. |
| **M1** — Static tree renders | ✅ Complete | Flex layout pass (constraints-down/sizes-up, sum-main/max-cross, leftover→Spacer), concrete `Painter` over SDL3 renderer + TTF, text measurement + rasterization. Counter UI appears laid out in the window (not yet clickable). |
| **M2** — Real input | ✅ Complete | SDL pointer events → hit-test rects → dispatch `OnClickBehavior` → `Invalidate` → rebuild → repaint. Clicking +/− updates the count. *Minimal GUI app goal reached.* |
| **M3** — Interaction states | ✅ Complete | Cross-axis alignment (`Center`, `AlignStart`, `AlignEnd`, `AlignStretch`), sizing constraints (`Width`, `Height`, `FixedSize` with `SizingConstraints`), and a draw-time-resolved interaction pipeline: `IfActive<T>` / `IfPressed` / `IfHover` record field-level `StatePatch` deltas blended at draw, a persistent state store keyed by `StableKey`, `Transition` animation with easing curves, `OnDrag` with pointer capture, and the **repaint-vs-rebuild split** (idle blocks in `SDL_WaitEvent`, ticks at ~60fps only while animating/dragging). Exit met: buttons highlight on hover with no rebuild; ~0% idle CPU. |
| **M4** — Persistent state: scroll | ✅ Complete | Building on M3's rebuild-surviving identity (`KeyAssign` → `StableKey` + retained `Node` tree): a `Scrollable` container primitive carrying a `ScrollView` marker, `Clip()` and `Vertical`/`Horizontal` as composable modifiers, mouse-wheel events dispatched by `ScrollTracker` to the nearest scrollable under the pointer, a persistent per-key scroll offset applied as a render-time translation (no relayout), `Painter` clip stack over `SDL_SetRenderClipRect`, `OnScroll` handler, and orphan eviction in `ReconcileTree()`. Exit met: a Todo app adds/removes items and scrolls a clipped list whose position survives the rebuild. |
| **M5** — Text input, focus, keyboard | 🔲 Future | Focus routing, caret, key events, editing. Depends on M4 identity. Exit: type into and edit a text field. |

## Earmarked (post-M5)

Memoization (only if profiled slow) · `Model<T>` observables + `Bind` ·
Live-reflow drag / layout-affecting animation (behind the M3 drag-offset seam) ·
Image/asset pipeline · Complex-object primitives · Accessibility ·
**Renderer/platform abstraction + alternate backend** (extracted from concrete `Painter`
once the concatenative model is proven).

Delivered ahead of schedule in M3: basic **animation** (`Transition` + easing) and a
**drag protocol** (`OnDrag` + pointer capture), both previously earmarked here.

## Constraint checkpoints

- M1: Rects on transient widgets (freed with arena) ✅
- M3: Cross-axis alignment + sizing constraints ✅
- M3: Interaction state resolved at draw via `StatePatch` (IfPressed / IfHover) ✅
- M3: Repaint loop reuses the tree; idle blocks at ~0% CPU ✅
- M4: Orphan eviction via `ReconcileTree()` — matched Nodes are reused, absent keys are disposed; stale state slots and clocks are pruned from reused Nodes whose `IInteractionState` references have changed; clocks self-prune once settled ✅
- Post-M2/M5: Profile before any memoization/observer work
