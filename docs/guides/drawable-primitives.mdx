title: Drawable Primitives
description: Tier 3 — a Component with Measure/Draw overrides for custom rendering
---

For custom rendering, subclass `Component` and override its virtual hooks. This is the rare
case; most widgets are factored words (Tier 1), not new drawable primitives. The goal is to
provide an escape hatch for pixel-level drawing without forcing every widget author to learn
a renderer abstraction.

## The Component hooks

`Component` provides virtual methods that framework passes call into:

```beef
public abstract class Component
{
    public virtual void Describe(String str) { }
    public virtual Size Measure(Size constraint) { ... }
    public virtual void DrawBackground(Painter painter, Widget widget, Rect rect) { }
    public virtual void DrawContent(Painter painter, Widget widget, Rect rect) { }
    public virtual void DrawOverlay(Painter painter, Widget widget, Rect rect) { }
}
```

| Hook | Called by | Purpose |
|---|---|---|
| `Describe` | `TreeDump` | Human-readable description string |
| `Measure` | Layout pass | Return intrinsic size |
| `DrawBackground` | Paint pass (z-order: back) | Fill, background color |
| `DrawContent` | Paint pass (z-order: middle) | Text, custom drawing |
| `DrawOverlay` | Paint pass (z-order: front) | Borders, debug overlays |

Note that `Measure` and the `Draw*` hooks receive the `Widget` in addition to `Painter` and
`Rect` — this lets your component query the widget's Property bag for styling data (e.g.
`TextComponent` reads `TextStyleProperty` for color).

## A minimal drawable: filled rectangle

```beef
public class FilledRect : Component
{
    public Color FillColor = .White;

    public override void DrawBackground(Painter painter, Widget widget, Rect bounds)
    {
        painter.FillRect(bounds, FillColor);
    }

    public override void Describe(String buf)
    {
        buf.AppendF($"fill={FillColor}");
    }
}
```

Then a word to make it usable:

```beef
extension UI
{
    public static void FilledRect(Color c)
    {
        NewWidget("FilledRect");
        AttachComponent(new:BuildAlloc FilledRect() { FillColor = c });
    }
}
```

## A more complete example: custom progress bar

```beef
public class ProgressBar : Component
{
    public float Progress;     // 0.0 – 1.0
    public Color FillColor = .Blue;
    public Color TrackColor = .(60, 60, 60, 255);

    public override void DrawBackground(Painter painter, Widget widget, Rect bounds)
    {
        // Track (full width, grey)
        painter.FillRoundRect(bounds, 4, TrackColor);
    }

    public override void DrawOverlay(Painter painter, Widget widget, Rect bounds)
    {
        // Fill (proportional width, colored)
        float fillWidth = bounds.Width * Progress;
        let fillRect = Rect(bounds.X, bounds.Y, fillWidth, bounds.Height);
        painter.FillRoundRect(fillRect, 4, FillColor);
    }

    public override void Describe(String buf)
    {
        buf.AppendF($"progress={Progress * 100}%");
    }
}

extension UI
{
    public static void ProgressBar(float progress)
    {
        NewWidget("ProgressBar");
        AttachComponent(new:BuildAlloc ProgressBar() { Progress = progress });
    }
}
```

Usage:

```beef
VStack(scope () => {
    ProgressBar(0.75f); Width(.Percent(1.0f)); FixedSize(0, 20);
});
```

## Querying the Property bag from a Component

Your `Component` can read the widget's Property bag for styling data. The framework's
`TextComponent` does this:

```beef
public override void DrawContent(Painter painter, Widget widget, Rect bounds)
{
    var ts = widget.GetProperty<TextStyleProperty>();
    Color color = ts != null ? ts.TextColor : .Black;
    painter.DrawText(Content, bounds.X, bounds.Y, color);
}
```

This pattern lets your drawable primitive respect modifier words: a user who writes
`ProgressBar(0.5f); TextColor(.Green);` gets a green progress bar if your `DrawOverlay`
reads `TextStyleProperty` for its fill color.

## The Painter API

The `Painter` class (in `src/Core/Painter.bf`) wraps SDL3 rendering:

| Method | Description |
|---|---|
| `FillRect(Rect, Color)` | Filled rectangle |
| `FillRoundRect(Rect, float radius, Color)` | Filled rounded rectangle |
| `DrawRect(Rect, Color)` | Rectangle outline |
| `DrawRoundRect(Rect, float radius, float width, Color)` | Rounded rectangle outline |
| `DrawText(StringView, float x, float y, Color)` | Render text (uses active TTF font) |
| `MeasureText(StringView)` | Get pixel size of text |

Currently, `Painter` is a concrete class over SDL3 with no abstraction. Direct access is fine
for experiments; the eventual renderer abstraction will extract a common interface from
working code.

## When to use Tier 3

- You need custom pixel drawing that existing components (`TextComponent`, `Interior`,
  `Boundary`) don't cover
- You need to combine background and overlay drawing in a specific way
- You're building a completely new visual primitive (progress bar, slider track, chart)

If you can achieve the visual with `Background { ... }` + `Border { ... }` on an existing
widget, do that instead; it's simpler and doesn't require a new class.
